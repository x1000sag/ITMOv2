# Нагрузочные проверки

Примечание по терминологии: SR — время ответа API (мс).

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Базовая нагрузка | 10 rps, 5 минут | SR: p50 ≤ N мс, p95 ≤ 200 мс, p99 ≤ N мс; 5xx = 0%; абсолютный тайм‑аут запроса ≤ N с | SR p50/p95/p99, 5xx | Отчёт нагрузки |
| Спайк | 50 rps, 2 минуты | SR: p50 ≤ N мс, p95 ≤ 500 мс, p99 ≤ N мс; 5xx = 0% | Устойчивость под пиком; SR p50/p95/p99; 5xx | Графики APM |
| Ramp‑up | 1 → 50 rps, шаг N rps/мин, 10 минут | Рост ошибки без скачков; SR укладывается в пороги из базовой/спайк; 5xx = 0% | SR p50/p95/p99 по ступеням; 5xx | Отчёт нагрузки |
| Soak | 10 rps, 30 минут | Деградация SR отсутствует (>N% от базовой — fail); 5xx = 0% | SR тренд, 5xx; ресурсоёмкость N | Графики APM |
| Границы API (API‑1) | 1 rps, 1 мин; diff > 20 000 символов | 413 в 100% таких запросов; 5xx = 0%; политика 422 — N (уточнить) | Доля 413/422 на границах | Отчёт нагрузки |
| Отказ/таймаут LLM (REL‑1) | 5 rps, 1 мин; симулировать LLM > 10 с и ошибки | Контролируемый ответ ≤ 10 с; 5xx = 0% | Таймауты/ошибки LLM, время ответа API | Автотест (REL‑1) |
| Безопасность под нагрузкой (SEC‑1, OBS‑1) | 10 rps, 5 мин; в diff — тестовые секреты | В промпте к LLM секреты замаскированы ([REDACTED]); в логах только request_id, длительность, статус | Маскирование до LLM; отсутствие недопустимого логирования | Автотест (SEC‑1, OBS‑1) |

Если нагрузочное тестирование пока не требуется, обоснуйте это и назовите условие, после которого оно понадобится.

Метрики и артефакты (воспроизводимость):
- APM дашборды: N (ссылка/название)
- Инструмент нагрузки: N (k6/locust); скрипт: N; команда запуска: N
- Артефакты: отчёт и сырой результат теста сохраняются в N (путь/ссылка)
