# Стратегия нагрузочного тестирования

## Критерии приёмки (SLO)

- Латентность: p50/p95/p99 по ключевым эндпойнтам — целевые пороги уточнить. Абсолютный тайм-аут запроса T_req — уточнить.
- Ошибки: 5xx ≤ уточнить. Разрешённые 4xx (например, 413/422 на валидных границах) ≤ уточнить.
- Устойчивость: отсутствие деградации по памяти/очередям в долгом прогонах (дрейф ≤ уточнить).

## Метрики и артефакты

- Источники метрик: APM/трейсинг (CPU, память, GC, очередь, внешние вызовы), метрики приложения (таймауты к внешнему LLM), метрики стенда.
- Инструмент: k6 (или эквивалент). Команда запуска и параметры окружения — уточнить; зафиксировать в README сценариев.
- Артефакты: сохранять отчёты и «сырые» результаты в каталоге artifacts/load/<дата_прогона>/; приложить ссылки на дашборды APM.

## Сценарии

| Сценарий | Нагрузка и длительность | Критерии (SLO) | Что измеряем | Артефакты |
|---|---|---|---|---|
| Прогрев | Ramp-up 0 → базовая нагрузка, 2–5 мин | Без ошибок 5xx; стабилизация p95 | Латентность по минутам, прогрев кешей/соединений | Отчёт нагрузки |
| Базовая | 10 rps, 5 мин | p50/p95/p99 в пределах SLO; 5xx=0; 4xx ≤ уточнить | Распределение латентности, таймауты LLM | Отчёт + графики APM |
| Пик (спайк) | 50 rps, 2 мин | p95 в пределах SLO; 5xx=0; отсутствие исчерпания ресурсов | Устойчивость под спайком, очереди | Графики APM |
| Soak | Базовая/слегка повышенная, 60 мин | Нет роста памяти/очередей; стабильный error rate | Память, GC, latency drift | Отчёт + APM |
| Границы | Большие payload/диффы, близкие к лимитам | Для >20k символов diff — HTTP 413 (API-1); корректные 422/413 на валидации | Быстрые отказы, доли 413/422 | Логи прогона + APM |
| Отказы внешнего LLM | Симулировать таймаут 10 с (REL-1) | Контролируемый ответ ≤ 10 с; без падений | Ошибки интеграции, деградация латентности | Отчёт + логи |
| Безопасность под нагрузкой | Вход с «секретами» в diff | Секреты маскированы до вызова внешнего LLM (SEC-1) | Отсутствие секретов в prompt | Отчёт проверки |

## Методология запуска

1. Подготовить стенд и переменные окружения (BASE_URL, токены тестовых сервисов; без настоящих секретов).
2. Выполнить последовательность: прогрев → базовая → спайк → soak. Отдельно прогнать «Границы» и «Отказы внешнего LLM».
3. Сохранить отчёты и ссылки на дашборды в artifacts/load/<дата_прогона>/README.md. Зафиксировать версию сценариев и параметров.
