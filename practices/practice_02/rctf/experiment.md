# R.C.T.F.

## Полный запрос

- Role: Инженер по нагрузке на сервис
- Context: Сервис AI‑помощника ревьюера PR (FastAPI): принимает diff и формирует prompt для внешнего LLM, возвращает summary/risks/checks. Актуальные правила из Context Pack Практики 1: OUT-1 (структура ответа), SEC-1 (маскирование секретов до LLM), API-1 (отклонять diff > 20 000 символов, HTTP 413), REL-1 (таймаут внешнего LLM 10 с, контролируемый ответ), QA-1 (риски подтверждаются строками diff/правилами), OBS-1 (не логировать содержимое diff и ответа). Улучшаемый артефакт: файл Практики 1 [Нагрузочные проверки](../../practice_01/tests_load.md). Цель — сделать стратегию воспроизводимой: измеримые SLI/SLO, сценарии (прогрев/база/спайк/soak/границы/отказы/безопасность), методология запуска, источники метрик и артефакты.
- Task: Конкретизировать и переписать документ «Нагрузочные проверки» минимальными правками: сформулировать измеримые SLI/SLO (без выдумывания чисел — использовать «N»), расширить набор сценариев с критериями pass/fail, указать источники метрик и артефакты, описать методологию запуска. Результат — готовый для замены текст файла `practices/practice_01/tests_load.md`.
- Format: Верни один Markdown‑документ, который можно целиком подставить вместо текущего `tests_load.md`. Структура результата:
  1) Заголовок «Нагрузочные проверки».
  2) Раздел «Критерии приёмки (SLO)» с SLI: p50/p95/p99 латентности по ключевым эндпойнтам, абсолютный тайм‑аут запроса T_req, допустимые 5xx и допустимые 4xx (включая 413/422), пометки «N» вместо чисел.
  3) Раздел «Метрики и артефакты»: источники метрик (APM/трейсинг: CPU/память/GC/очереди/внешние вызовы; метрики приложения: таймауты к внешнему LLM; метрики стенда), инструмент (например, k6), где и как сохранять отчёты (artifacts/load/<дата_прогона>/) и ссылки на дашборды.
  4) Раздел «Сценарии» с таблицей столбцов: Сценарий | Нагрузка и длительность | Критерии (SLO) | Что измеряем | Артефакты. Включить как минимум: Прогрев, Базовая, Пик (спайк), Soak (60 мин — «N»), Границы (в т.ч. API-1: 413 для >20k), Отказы внешнего LLM (REL-1, контролируемый ответ ≤ 10 с), Безопасность под нагрузкой (SEC-1: секреты маскированы до LLM).
  5) Раздел «Методология запуска» с шагами подготовки стенда, последовательностью прогона и фиксацией версий/параметров.
  6) Раздел «Примечания» с терминологией: не использовать «SR», явно указывать percentiles и error rate; численные пороги помечать «N» и согласовывать отдельно.
  Правила ответа: только целевой Markdown без вступлений и пояснений, по‑русски, лаконично, без выдумывания чисел, учитывая OUT-1/SEC-1/API-1/REL-1/QA-1/OBS-1.

Ответ записать в [файл](./tests_load.md)
