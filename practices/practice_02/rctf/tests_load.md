## Критерии приёмки (SLO)

- SLI по латентности (мс) для ключевых эндпойнтов FastAPI:
  - POST /review: p50 — уточнить, p95 — уточнить, p99 — уточнить
  - Вызов внешнего LLM (внутренняя операция): p50 — уточнить, p95 — уточнить, p99 — уточнить
- Абсолютный тайм‑аут запроса T_req: уточнить
- Доля ошибок 5xx за интервал прогона: уточнить
- Доля допустимых 4xx: уточнить
  - Включая API‑1: HTTP 413 для diff > 20 000 символов — ожидаемые срабатывания считаются допустимыми
  - Включая 422 на невалидный ввод — допустимая доля уточнить
- REL‑1: при таймауте внешнего LLM контролируемый ответ формируется ≤ 10 с
- SEC‑1: секреты маскированы до отправки во внешний LLM (проверяется эвиденсом в логах/трейсах без содержимого)
- OBS‑1: содержимое diff и ответа не логируется

## Метрики и артефакты

- Источники метрик:
  - APM/трейсинг: CPU, память, GC, длина очередей, соединения, внешние вызовы (LLM), ошибки
  - Метрики приложения: счётчики таймаутов/ошибок внешнего LLM, доля 413/422, распределения латентности по эндпойнтам
  - Метрики стенда: утилизация ноды/подов, лимиты/requests, сетевые ошибки, диск/IO
- Инструмент нагрузки: k6 (или эквивалент) — скрипты в репозитории
- Артефакты прогона:
  - Полные отчёты k6 (json/html)
  - Экспорт метрик/трейсов (ссылки/снимки дашбордов)
  - Сводка SLI/SLO и pass/fail по сценариям
- Хранение: artifacts/load/<дата_прогона>/ с подпапками per‑scenario и README с параметрами запуска и версиями
- Дашборды: ссылки на APM/трейсинг/метрики — уточнить

## Методология запуска

1. Подготовка стенда:
   - Зафиксировать версии сервиса, образов, конфигураций и k6-скриптов (git SHA, теги)
   - Уточнить целевые значения SLO и нагрузочные профили
   - Настроить сбор метрик/трейсинга и дашборды; проверить, что логи не содержат diff/ответов (OBS‑1)
   - Подготовить тестовые данные: диффы нормальные, >20 000 символов, невалидные; входы с фальш‑секретами
2. Прогон сценариев в последовательности: Прогрев → Базовая → Пик → Soak → Границы → Отказы внешнего LLM → Безопасность
3. Для каждого сценария:
   - Запустить профиль k6 с фиксированными параметрами; записать timestamp и параметры
   - Зафиксировать SLI, ошибки, ключевые события; сохранить отчёты и ссылки на дашборды в artifacts/load/<дата_прогона>/
   - Определить pass/fail по разделу «Критерии (SLO)»; зафиксировать решение в сводке
4. По завершении: собрать сводный отчёт по SLI/SLO, выявить узкие места и завести действия на улучшения

## Примечания

- Не использовать термин «SR»; явно указывать percentiles (p50/p95/p99) и error rate
- Численные пороги помечать «уточнить» и согласовывать отдельно с командой
- Соответствие OUT‑1/SEC‑1/API‑1/REL‑1/QA‑1/OBS‑1 проверять в каждом прогоне через измеримые признаки
