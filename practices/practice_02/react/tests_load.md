# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Базовая нагрузка | 10 rps, 5 минут | SR ≤ 200 мс p95; SR ≤ N мс p50/p99; 0% 5xx; 4xx — только 413 при >20k (см. API-1) | Время ответа, доля 413/422, таймаутов LLM | Отчёт нагрузки |
| Пик | 50 rps, 2 минуты | SR ≤ 500 мс p95; SR ≤ N мс p50/p99; 0% 5xx | Устойчивость под пиком | Графики APM |
| Ramp | 10→50 rps, N минут | Без деградации SLI; 0% 5xx; 4xx — только 413 при >20k (API-1) | Поведение при постепенном росте нагрузки | Отчёт нагрузки |
| Soak | N rps, N часов | SR стабилен; отсутствие утечек; 0% 5xx | Долговременная стабильность (память/ресурсы) | Графики APM |
| Границы API | diff ≤/＞ 20 000 символов | ≤20k → 2xx; ＞20k → 413 (API-1); 0% 5xx | Политика 4xx и границы входа | Отчёт + логи без содержимого (OBS-1) |
| Отказы LLM | Имитация таймаута/исключения | Контролируемый ответ ≤ 10 с (REL-1); формат OUT-1; 0% 5xx | Обработка таймаутов/ошибок LLM и формат результата | Примеры ответов + логи метрик (OBS-1) |

Если нагрузочное тестирование пока не требуется, обоснуйте это и назовите условие, после которого оно понадобится.

## Артефакты воспроизводимости

- Скрипт/план нагрузки с версиями и параметрами (rps, длительности, данные).
- Экспорт APM/метрик и отчёт нагрузки с указанием commit/tag и среды выполнения.
- Логи с request_id, длительностью и статусом (без содержимого diff/ответов, см. OBS-1).
