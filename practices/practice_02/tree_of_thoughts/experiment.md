# Tree of Thoughts

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Решение, для которого нужны альтернативы:
- Минимальный набор правок в [Файл](../../practice_01/tests_load.md), который делает документ однозначным и воспроизводимым (SLI/SLO, сценарии baseline/ramp/spike/soak/границы/отказы, метрики и артефакты), с соблюдением контекст‑пака.
- Критерии выбора:
  - Минимальность правок (не переписывать документ целиком без необходимости).
  - Проверяемость и воспроизводимость (ясные pass/fail, артефакты и источники метрик).
  - Соответствие [Context Pack](../../practice_01/context.md) (OUT-1, SEC-1, API-1, REL-1, QA-1, OBS-1).
  - Однозначность терминов (без двусмысленностей вроде «SR» без определения).
  - Не выдумывать числа — помечать как «N».

## Запрос

Работай строго по методике Tree of Thoughts (ToT): формируй и оценивай альтернативы на ключевых узлах решения, расширяй только лучшие ветви, фиксируй явные критерии оценки и обоснование выбора. Не используй ReAct, CoT, RCTF, COV — только ToT с деревом альтернатив.

Входы и контекст:
- Улучшаемый артефакт: [Файл](../../practice_01/tests_load.md).
- Context Pack: [Context Pack](../../practice_01/context.md) (правила OUT-1, SEC-1, API-1, REL-1, QA-1, OBS-1).
- При необходимости фактов: [DIFF](../../practice_01/TRAINING_PR.diff).
- Выход для результата: [Вывод](./tests_load.md) (сюда записать итоговую версию документа минимальными правками).

Ключевые решения (ветвления дерева мыслей):
1) Как сформулировать SLI/SLO и критерии приёмки без выдумывания чисел (p50/p95/p99, error rate 5xx, политика 4xx на границах API-1, абсолютный тайм‑аут запроса/LLM из REL-1).
2) Какие сценарии включить и как их кратко описать: Прогрев, Базовая, Пик (спайк), Ramp‑up, Soak, Границы API (413/422), Отказ/таймаут внешнего LLM (REL‑1), Безопасность под нагрузкой (SEC‑1/OBS‑1).
3) Как зафиксировать «Метрики и артефакты» так, чтобы воспроизвести запуск: источники метрик/дашборды APM, инструмент (k6/Locust — помечать «N»), команда запуска, каталог/ссылки артефактов.
4) Как снять двусмысленности терминов (например, определить «SR» или заменить на «время ответа API»), сохраняя стиль исходника.

Правила ветвления и оценки:
- На каждом ключевом решении сгенерируй минимум 3 альтернативы (A/B/C). Для каждой заполни: краткое описание, плюсы, минусы, оценка по критериям (по шкале 1–5 для: минимальность, проверяемость, соответствие контекст‑паку, однозначность).
- Выбери top‑2 альтернативы по суммарной оценке и при необходимости скомбинируй их на следующем уровне дерева. Прекращай расширение, когда одна альтернатива явно доминирует по критериям и даёт минимальные правки.
- Все численные пороги, не заданные в контексте, помечай «N». Сохраняй исходные принятые числа, если они уже есть в документе.

Формат вывода (соблюдать структуру этого файла):
1) «Внешне описанные альтернативы» — заполни таблицу ниже (минимум A/B/C для каждого ключевого решения; при необходимости добавь строки). В «Оценка по критериям» укажи баллы и краткое обоснование.
2) «Выбор» — для каждого ключевого решения зафиксируй выбранную альтернативу/комбинацию, почему выбрана и как проверим (конкретная проверка/артефакт).
3) «Что изменили в исходном артефакте» — перечисли точные минимальные правки: файл/раздел, изменение, что осознанно отклонено.
4) Итоговую версию документа запиши в [Вывод](./tests_load.md) (без выдуманных чисел; помечай «N» там, где требуется согласование).

Границы и запреты:
- Не переписывай документ целиком без причины; следуй принципу минимальных правок.
- Не придумывай числа; помечай «N» и указывай, где зафиксировать позже.
- Соблюдай контекст‑пак (OUT-1, SEC-1, API-1, REL-1, QA-1, OBS-1) и не нарушай SCOPE‑1.

## Выбор

- Выбранная альтернатива:
  - 1) Комбинация A+B: добавить раздел SLI/SLO и явно определить «время ответа API» вместо SR. Числа из исходника сохраняем; недостающие помечаем «N». REL‑1 таймаут LLM=10s — факт.
  - 2) A: расширить таблицу сценариев шестьью краткими строками (Warm‑up, Ramp‑up, Soak, 413/422, LLM timeout/failure, Security under load). Существующие «Базовая» и «Пик» не менять по числам.
  - 3) A: добавить раздел «Метрики и артефакты» с источниками метрик, инструментом=N, командой запуска=N, каталогом артефактов.
  - 4) A: заменить термин «SR» на «время ответа API (Response Time)» в таблице.
- Почему:
  - Минимальные локальные правки без переписывания документа, при этом появляются однозначные SLI/SLO, воспроизводимость и соответствие Context Pack (API‑1, REL‑1, SEC‑1, OBS‑1).
- Как проверим:
  - Сравнить исходную и итоговую версии: наличие разделов SLI/SLO и «Метрики и артефакты», замена «SR», добавленные строки сценариев.
  - Прогнать сценарии с инструментом=N; собрать артефакты в каталоге=N; проверить APM‑дашборд=N на p95/p99 и 5xx; проверить кейсы 413/422 и LLM timeout≤10s.
