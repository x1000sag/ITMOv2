# Рефлексия по практике

Невероятные муки. Были проблемы с выделением своих скилов по результатам диалога в чате с агентом -- он просто не пердаёт нужный контекс (в частности как запускать субагентов). При вопросах к тому, как настроить вполне конкретную область (например hook) прихзодилось ловить галлюцинации ИИ, потому что тот думал, что всё настроено и работает.

## Контекст

- Проект: Kanban CLI (C#)
- Цель: 2 ADR (доменные классы; CLI UI), собственный MCP (TypeScript) для хождению по ./docs, подключение внешнего MCP (context7), запуск watcher/runner

## Подключения и применение

- Skills, которые использовались:
  - find-skills -- для поиска/подключения skills (описать, какие нашли и зачем)
  - dotnet-runner -- для build/test/run .NET проектов
  - watch-runner -- для автопроверок при изменениях
  - dotnet-best-practices -- для продвинутого написания кода на C#
- MCP:
  - Локальный mcp-docs-ts -- чтение/поиск по ./docs (docs.list/docs.read/docs.search)
  - Внешний context7 -- справка по C#/.NET
- Оркестрация:
  - Orchestrator + субагенты (Docs/Spec, Code, Test) -- кто что делал и как взаимодействовали

## Что помогло

- Сохрание контекста о проекте из-за Agents, разграничение на ответственности агентамб skills
- Конкеретные примеры: find-skills для поиска скилов под описание проекта. dotnet-best-practices для формирование ADR и имплементации. 

## Что мешало

- старая версия opencode (или недостаток знания нейронки об документации), галлюцинации нейронки при выстраивыании окружения, неисполнение роли (поставлена одна задача, а он выполняет несколько). подключение через WSL
- ручная проверка, настройка; полумеры и костыли (например закинуть плагин для opencode в скил для нейронки, потому что opencode не хочет подавать сигналы в плагин, как ожидалось); Принудительная остановка агента.

## Где пришлось вмешаться

- Компромиссы и принятые ограничения: плагин opencode в скил. Отказ от внешнего MCP (невозможность использовать)
