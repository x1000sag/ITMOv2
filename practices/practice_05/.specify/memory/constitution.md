# Конституция проекта Kanban

## Core Principles

### I. Простота и минимализм (YAGNI)
Проект следует принципу "You Aren't Gonna Need It". Мы реализуем только необходимый функционал для текущих требований. Сложные абстракции добавляются только при наличии явной необходимости. Удаление и архивирование карточек/колонок выходят за рамки MVP.

### II. Консистентность доменной модели
Все артефакты (код, спецификации, документация, ADR) должны отражать единую доменную модель: Board, Column, Card. Карточки перемещаются только между колонками без позиционирования внутри колонки. Имена колонок уникальны в рамках доски. Теги в карточке уникальны.

### III. Тестируемость
Код должен быть структурирован для тестирования. Доменные правила инкапсулируются явно. Критичная логика покрывается тестами. При добавлении новой функциональности сначала рассматривается её тестируемость.

### IV. Атомарность хранения
Данные хранятся в единственном локальном файле `data/board.json`. Запись должна быть атомарной для минимизации риска порчи файла при прерывании. Сериализация использует JSON с корректной обработкой DateOnly/DateTime.

### V. Понятность интерфейса
CLI должен возвращать ненулевой код выхода при ошибке и выводить понятное сообщение пользователю. Валидация ввода происходит на границе системы с понятными ошибками. Поддерживается человекочитаемый формат вывода.

### VI. Эволюционируемая архитектура
Текущая архитектура (Domain/Infrastructure/Cli) заложена с расчётом на эволюцию в C# backend + Vue frontend. Модель данных должна оставаться совместимой при переходе к веб-версии. Авторизация через профиль/куки и возможность перехода на БД рассматриваются как будущие направления развития.

## Технологический стек

- **Backend (текущий)**: C# / .NET
- **Текущая структура**: Clean-подход с разделением на `Kanban.Domain`, `Kanban.Infrastructure`, `Kanban.Cli`
- **Хранение (текущее)**: Локальный JSON-файл `data/board.json`
- **Frontend (планируемый)**: Vue 3 + Vite + TypeScript в каталоге `frontend/`
- **Тестирование**: xUnit
- **Язык артефактов**: Русский язык для всей документации, спецификаций, ADR

## Архитектура и хранение

- **Единый источник данных**: Только одна доска, хранится в одном файле. Множественные доски и синхронизация не поддерживаются в рамках текущего дизайна.
- **Формат данных**: JSON со схемой Board → Columns[] → Cards[]. Card содержит id (UUID), title, description?, tags[], deadline? (YYYY-MM-DD), createdAt (UTC).
- **Ограничения MVP**: Перемещение карточек без позиционирования внутри колонки. Без фильтров, поиска, удаления карточек/колонок, архива.
- **Будущее развитие**: Переход к веб-архитектуре (C# backend API), Vue frontend, авторизация на основе профиля/куки, возможность использования БД вместо файлового хранения.

## Процесс разработки

- **Spec-Driven Development**: Для новой функциональности используется цикл Spec Kit: constitution → specify → clarify → plan → tasks → implement. Мелкие правки и документацию можно делать напрямую.
- **Минимальные изменения**: Точечные правки, избегать избыточной обратной совместимости без явной причины.
- **Документация**: При изменении поведения необходимо обновлять `docs/` и ADR для поддержания консистентности артефактов.
- **Качество**: Сборка и тесты должны проходить. Комментарии в коде только там, где они экономят время чтения.
- **Язык**: Весь код, комментарии в артефактах проекта, спецификации, коммиты (при наличии) — на русском языке в соответствии с принятыми конвенциями.

## Governance

Данная конституция определяет основные принципы и направления развития проекта Kanban. Изменения конституции требуют документирования через процесс обновления. Все решения в рамках разработки должны соответствовать изложенным принципам. При расхождении между конституцией и другими документами приоритет имеет конституция.
