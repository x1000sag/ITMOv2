# Спецификация: Исправление ошибок сборки

**Фича**: fix-build-errors  
**Номер**: 001  
**Статус**: Готова к планированию  
**Создано**: 2026-10-28

## Цель

Исправить все ошибки компиляции в проекте Kanban так, чтобы весь проект собирался, все тесты проходили, при этом никакая функциональность не была удалена.

## Проблема

Проект в текущем состоянии не собирается из-за:
1. Синтаксическая ошибка в `kanban-cli/src/Kanban.Cli/Program.cs` - лишняя закрывающая скобка
2. Проблемы с целевым фреймворком в окружении (.NET 10 вместо .NET 8) - требуется адаптация под доступную среду
3. Ошибки в реализации "богатой" доменной модели в `kanban-cli/Kanban.Domain/Board.cs` (неправильная работа с nullable value tuple)
4. Проблемы с окружением SDK (workload manifests)

## Функциональные требования

- **FR-001**: Проект должен собираться без ошибок компиляции во всех проектах решения
- **FR-002**: Все существующие тесты должны проходить
- **FR-003**: Никакая функциональность не должна быть удалена или вырезана
- **FR-004**: Исправления должны быть минимальными и целевыми
- **FR-005**: Обе реализации API (в `src/` и в корне `kanban-cli/`) должны оставаться работоспособными, если обе используются тестами

## Ключевые сущности

- Board, Column, Card - доменные сущности
- BoardRepository - работа с хранением
- CLI команды - интерфейс пользователя

## Критерии успеха

- **SC-001**: `dotnet build kanban-cli/Kanban.sln` завершается с кодом 0 и без ошибок
- **SC-002**: Все тесты из обоих тестовых проектов проходят успешно
- **SC-003**: CLI приложение функционирует со всеми существующими командами
- **SC-004**: Сохранена полная совместимость с существующими тестами

## Ограничения

- Не удалять функциональность
- Не менять логику работы, только исправлять ошибки компиляции/сборки
- Минимальные изменения
- Сохранить обе структуры проекта, если они обе нужны для тестов

## Допущения

- В окружении доступен .NET SDK 10.x
- Все тесты должны остаться валидными
- Исправления касаются только сборки, не требуют изменения требований
