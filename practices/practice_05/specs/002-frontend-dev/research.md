# Research: Разработка фронтенда (Vue)

**Feature**: 002-frontend-dev  
**Date**: 2026-10-28

## Решения по неопределенностям

### 1. Подход к работе с файловой системой из браузера

**Проблема**: Фронтенд в браузере не имеет прямого доступа к файлу `data/board.json` на диске. CLI работает с файлом напрямую. Необходимо обеспечить совместимость - оба должны работать с одним и тем же файлом.

**Варианты решения**:
1. **File System Access API** - современный API, позволяет браузеру читать/писать локальные файлы с разрешения пользователя. Работает не во всех браузерах, требует пользовательского взаимодействия.
2. **Backend API сервер** - создать простой HTTP API, который будет читать/писать `data/board.json`. Фронтенд будет обращаться к API.
3. **Electron/Tauri** - упаковать как десктопное приложение, но указано "веб-интерфейс".
4. **Использование localStorage с синхронизацией** - не подходит, т.к. нужен единый файл с CLI.

**Решение**: **Backend API сервер** (вариант 2)

**Обоснование**:
- Обеспечивает работу как с CLI, так и с веб-интерфейсом через один и тот же файл
- Атомарная запись как в CLI (можно переиспользовать логику из `Kanban.Infrastructure`)
- Кроссбраузерность
- Соответствует эволюционной архитектуре из конституции (переход к веб-архитектуре с C# backend API)

**Альтернативы отклонены**:
- File System Access API - ограниченная поддержка браузерами, требует разрешений
- Electron - избыточно для веб-интерфейса

**Детали реализации**:
- Backend API будет размещен в решении `kanban-cli/` (в том же решении, что и CLI)
- API endpoints: GET /api/board, PUT/PATCH /api/board для сохранения
- Атомарная запись через временный файл + rename (как в BoardRepository)
- Можно добавить новый проект `Kanban.Api` в `kanban-cli/src/` или добавить Web API в существующий проект

### 2. Технологический стек фронтенда

**Решение**: Vue 3 + Vite + TypeScript

**Обоснование**:
- Указано в спецификации (FR-001)
- Указано в конституции
- Современный, производительный стек
- Хорошая поддержка TypeScript
- Composition API для лучшей организации кода

**Дополнительные зависимости** (минимальные):
- Vue Router (если потребуется навигация) - вероятно не нужен, одна страница
- Pinia для управления состоянием - опционально, можно использовать Composition API
- Для drag-and-drop перемещения карточек - native HTML5 Drag and Drop API или библиотека (например, vue-draggable-plus). Предпочтительно native API для минимализма.

### 3. Совместимость формата данных

**Требование**: 100% совместимость с форматом CLI (SC-003)

**Анализ текущего формата** (из BoardRepository.cs):
```csharp
public class Board
{
    public string Name { get; set; }
    public List<Column> Columns { get; set; }
}

public class Column
{
    public string Name { get; set; }
    public List<Card> Cards { get; set; }
}

public class Card
{
    public Guid Id { get; set; }
    public string Title { get; set; }
    public string? Description { get; set; }
    public List<string> Tags { get; set; }
    public DateOnly? Deadline { get; set; }
    public DateTime CreatedAt { get; set; }
}
```

Сериализация в JSON - System.Text.Json. Нужно обеспечить идентичный формат:
- Tags - массив строк
- Deadline - может быть null, формат YYYY-MM-DD
- CreatedAt - DateTime в UTC
- Id - Guid

**Решение**: Создать TypeScript типы, полностью соответствующие C# модели. При сериализации/десериализации использовать тот же формат.

### 4. Атомарная запись

**Требование**: FR-007 - сохранение в атомарном режиме как в CLI

**Подход CLI** (из BoardRepository):
```csharp
// Запись во временный файл, затем перемещение
var tempFile = Path.GetTempFileName();
File.WriteAllText(tempFile, json);
File.Move(tempFile, _filePath, overwrite: true);
```

**Для веб-через API**: API должен реализовывать ту же логику атомарной записи.

## Рекомендации по реализации

1. **Структура**: Создать `frontend/` с Vue 3 + Vite + TypeScript
2. **API слой**: Нужно либо создать простой backend API, либо интегрировать в существующий проект. Учитывая, что в репозитории есть только CLI, вероятнее всего нужно создать отдельный API сервер (можно на Node.js/Express для простоты) в каталоге `backend/` или `api/`. Но в конституции упомянуто "переход к веб-архитектуре (C# backend API)" - возможно лучше использовать C# ASP.NET Core для консистентности со стеком.
3. **Типы**: Скопировать структуру доменной модели в TypeScript
4. **Стилизация**: Минимальная, на русском языке
5. **Drag & Drop**: HTML5 Drag and Drop API для перемещения карточек между колонками

## Открытые вопросы

- Будет ли создаваться backend API в рамках этой фичи или только frontend? Спецификация говорит "фронтенд должен работать с файлом данных", но как - не указано явно. Нужно уточнить, но по конституции и здравому смыслу для веб-приложения требуется API.
- Расположение backend API - `backend/` или интегрировать в `kanban-cli/`?

**Предварительное решение**: Создать минимальный C# ASP.NET Core Web API в `backend/` для работы с `data/board.json`, чтобы сохранить консистентность со стеком C#. Фронтенд будет обращаться к этому API.
