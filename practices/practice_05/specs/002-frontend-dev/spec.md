## User Scenarios & Testing *(mandatory)*

### User Story 1 - Просмотр доски Kanban (Priority: P1)

Пользователь открывает веб-интерфейс и видит доску с колонками и карточками в том же формате, что и в CLI.

**Why this priority**: Основной сценарий использования - просмотр текущего состояния доски. Без этого невозможно использовать фронтенд.

**Independent Test**: Можно протестировать, открыв фронтенд и убедившись, что отображаются колонки ToDo/InProgress/Done и карточки из data/board.json.

**Acceptance Scenarios**:

1. **Given** существует data/board.json с колонками и карточками, **When** пользователь открывает веб-приложение, **Then** на экране отображаются все колонки доски с карточками в них
2. **Given** карточка имеет заголовок, описание, теги, дедлайн, **When** она отображается во фронтенде, **Then** вся информация о карточке отображается пользователю

---

### User Story 2 - Взаимодействие с карточками (Priority: P2)

Пользователь может просматривать детали карточки, создавать, редактировать и перемещать карточки между колонками через веб-интерфейс.

**Why this priority**: Обеспечивает основную функциональность Kanban - управление карточками.

**Independent Test**: Можно протестировать создание карточки, её редактирование и перемещение между колонками.

**Acceptance Scenarios**:

1. **Given** пользователь находится на доске, **When** он создает новую карточку с заголовком, **Then** карточка появляется в выбранной колонке
2. **Given** карточка находится в колонке ToDo, **When** пользователь перетаскивает её в InProgress, **Then** карточка перемещается в соответствующую колонку
3. **Given** карточка существует, **When** пользователь редактирует её описание или теги, **Then** изменения сохраняются

---

### User Story 3 - Сохранение данных (Priority: P1)

Изменения, внесенные через веб-интерфейс, должны сохраняться в том же формате data/board.json, что использует CLI.

**Why this priority**: Критично для совместимости между CLI и веб-интерфейсом - они должны работать с одними и теми же данными.

**Independent Test**: Можно протестировать внесение изменений через фронтенд и проверку, что CLI видит эти изменения и корректно с ними работает.

**Acceptance Scenarios**:

1. **Given** пользователь внес изменения через фронтенд, **When** данные сохраняются, **Then** файл data/board.json обновляется в формате, совместимом с существующей моделью данных
2. **Given** данные изменены через фронтенд, **When** пользователь запускает CLI команды, **Then** CLI корректно отображает и обрабатывает эти данные

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять веб-интерфейс на Vue 3 + Vite + TypeScript
- **FR-002**: Фронтенд MUST отображать доску с колонками и карточками в соответствии с доменной моделью Board/Column/Card
- **FR-003**: Фронтенд MUST работать с файлом данных data/board.json в том же формате, что и CLI
- **FR-004**: Пользователь MUST иметь возможность создавать карточки с заголовком, описанием, тегами и дедлайном
- **FR-005**: Пользователь MUST иметь возможность перемещать карточки между колонками
- **FR-006**: Пользователь MUST иметь возможность редактировать карточки
- **FR-007**: Система MUST сохранять изменения в data/board.json в атомарном режиме (как в CLI)
- **FR-008**: Фронтенд MUST быть размещен в каталоге `frontend/` согласно конвенциям проекта
- **FR-009**: Доменная модель и формат данных MUST оставаться совместимыми с CLI

### Key Entities *(include if feature involves data)*

- **Board**: Доска с именем и списком колонок. Единый источник данных.
- **Column**: Колонка с именем и списком карточек. Имена колонок уникальны в рамках доски.
- **Card**: Карточка с id (UUID), title, description, tags[], deadline?, createdAt. Теги в карточке уникальны.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Фронтенд успешно отображает существующую доску из data/board.json без потери данных
- **SC-002**: Пользователь может создать, отредактировать и переместить карточку через веб-интерфейс за время, сопоставимое с CLI
- **SC-003**: Все изменения, сделанные через фронтенд, корректно читаются CLI и наоборот (100% совместимость формата данных)
- **SC-004**: Фронтенд собирается и запускается без ошибок используя npm скрипты из frontend/package.json

## Assumptions

- Frontend будет использовать тот же подход к хранению данных, что и CLI - работа с файлом data/board.json
- Для разработки фронтенда будет использован Vue 3 с Composition API
- Backend API может потребоваться для работы с файловой системой из браузера, или будет использоваться другой подход
- Существующая структура проекта и конвенции должны соблюдаться
- Язык интерфейса - русский, как и в остальном проекте
