# Спецификация: Интеграция веток dev/practice_05-back и dev/practice_05-front

**Ветка фичи**: `004-integrate-back-front`

**Создано**: 2026-10-28

**Статус**: Draft

**Исходное описание**: Есть ветки dev/practice_05-back и dev/practice_05-front, где реализованы 2 разные фичи. Необходимо спланировать их интеграцию merge

## Пользовательские сценарии и тестирование *(обязательно)*

### История пользователя 1 - Проанализировать изменения в ветках (Приоритет: P1)

Как разработчик, я хочу понять, какие файлы и функциональность реализованы в каждой ветке, чтобы оценить объем интеграции и потенциальные конфликты.

**Почему этот приоритет**: Без анализа невозможно спланировать корректный merge.

**Независимый тест**: Можно выполнить анализ структуры веток и получить отчет о изменениях.

**Сценарии приемки**:

1. **Дано** есть ветки dev/practice_05-back и dev/practice_05-front, **Когда** проводится анализ, **Тогда** определены все добавленные/измененные файлы в каждой ветке относительно общей базы
2. **Дано** проведен анализ, **Когда** формируется отчет, **Тогда** выявлены потенциальные конфликты слияния

---

### История пользователя 2 - Спланировать стратегию слияния (Приоритет: P1)

Как разработчик, я хочу получить план интеграции двух фич, чтобы выполнить merge безопасным и предсказуемым образом.

**Почему этот приоритет**: План необходим для корректной интеграции без потери функциональности.

**Независимый тест**: Можно проверить наличие плана с конкретными шагами, списком конфликтов и решением по каждому.

**Сценарии приемки**:

1. **Дано** есть анализ веток, **Когда** составляется план, **Тогда** определен порядок слияния (какую ветку сливать первой)
2. **Дано** есть план слияния, **Когда** в нем описаны конфликты, **Тогда** для каждого конфликта предложен способ разрешения
3. **Дано** есть план слияния, **Когда** он готов, **Тогда** в нем указаны проверки после слияния (сборка, тесты)

---

### История пользователя 3 - Выполнить интеграцию и проверить работоспособность (Приоритет: P1)

Как разработчик, я хочу слить обе ветки в integration/practice_05 и убедиться, что обе фичи работают вместе.

**Почему этот приоритет**: Цель - получить работающее объединенное решение.

**Независимый тест**: Можно собрать решение и запустить тесты, убедившись что нет регрессий и обе фичи доступны.

**Сценарии приемки**:

1. **Дано** есть план слияния, **Когда** выполнено слияние обеих веток, **Тогда** решение компилируется без ошибок
2. **Дано** решение собрано, **Когда** запущены тесты, **Тогда** все существующие и новые тесты проходят
3. **Дано** интеграция выполнена, **Когда** проверяется функциональность, **Тогда** доступны как UserProfile API (из back-ветки), так и Vue frontend (из front-ветки)

---

### Крайние случаи

- **Конфликт в Kanban.sln**: Обе ветки добавляют проекты в solution файл - требуется ручное разрешение
- **Разные API проекты**: В front-ветке добавлен Kanban.Api, в back-ветке добавлен UserProfile.Api - должны сосуществовать
- **Совместимость форматов данных**: Нужно убедиться, что frontend и API используют согласованные типы/форматы
- **Зависимости**: Проверить конфликты в package.json, .csproj файлах

## Требования *(обязательно)*

### Функциональные требования

- **FR-001**: Система ДОЛЖНА содержать анализ отличий веток dev/practice_05-back и dev/practice_05-front от общей базы
- **FR-002**: Система ДОЛЖНА определить потенциальные конфликты при слиянии
- **FR-003**: Система ДОЛЖНА содержать план слияния с порядком операций и способом разрешения конфликтов
- **FR-004**: После слияния решение ДОЛЖНО успешно собираться командой `dotnet build kanban-cli/Kanban.sln`
- **FR-005**: После слияния все тесты ДОЛЖНЫ проходить командой `dotnet test kanban-cli/Kanban.sln`
- **FR-006**: После интеграции ДОЛЖНЫ быть доступны компоненты обеих фич: UserProfile API и Vue frontend для Kanban
- **FR-007**: Конфигурация проектов в Kanban.sln ДОЛЖНА корректно включать все добавленные проекты

## Предположения

- Общая база веток понятна через анализ истории коммитов
- Конфликты главным образом в Kanban.sln и возможно в других общих файлах
- Обе фичи независимы и могут сосуществовать в одном решении
- Текущая ветка integration/practice_05 является целевой для слияния

- Сохранить функциональность обеих фич
